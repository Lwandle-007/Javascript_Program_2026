# Javascript_Program_2026

A browser-based portal that helps learners stay on top of their studies. Built with JavaScript and Firebase, it covers login, progress tracking, task management, search, saved preferences, and a couple of mini-games — all built together as a team on GitHub.

## Project Title
**SkillsTrack Learner Support Portal** (Javascript_Program_2026)

## Project Overview
The Learner Support Portal is a simple, browser-based space where learners can stay connected, find resources, and keep track of their progress. It lets people sign up, log in, and see their own information. Everything is powered by JavaScript on the front end and Firebase on the back end.

## Client Brief Summary
The client wanted a portal where learners can:
- Talk to teachers and stay in touch
- Keep track of their own progress
- Get access to study materials
- Have a bit of fun with quizzes and mini-games along the way

## Project Objectives
- Let learners register, log in, and safely view their own information
- Store, update, fetch, and delete data using Firebase — including progress summaries and an interactive mini-game

## Git Branching Strategy

- **main** – the protected branch. Only finished, production-ready code goes here.
- **Branches** – each developer works in their own feature branch until their piece is done.
- **hilda** – Hilda's personal branch for her own work.
- **lwandle** – Lwandle's personal branch for his own work.
- **onkarabetse** – Onkarabetse's personal branch for her own work.

    Each of us does our own work on our own branch first. Nothing goes straight to main. 
    Once a piece of work is finished and tested on a personal branch, it gets merged into main through a pull request.

## Contribution Guidelines
- Do your work on your own named branch (hilda, lwandle, or onkarabetse) — not on main
- Commit often, with clear messages so the others know what changed
- move work to main once it's finished and working, not halfway through
- Nobody pushes directly to main — even once work is finalized, it goes in through a pull request
- Open a pull request, get it reviewed by at least one other team member, and merge once it's approved
- If there's a conflict, sort it out locally on your own branch before opening the pull request — never force-push over someone else's work
